# Prompt: Discrete Math Games (Nodeland), validated puzzles with research logging

> **About this prompt.** This is the design specification for `dmath-games.html`, written as one reusable prompt. The original game was built over several turns. This prompt combines those requirements and the decisions made along the way, so an AI coding assistant can regenerate an equivalent game in one pass. Edit the bracketed parts to change the topic, the codes or the story.

---

## Role
You are an expert in educational game design and front-end engineering, building classroom tools for undergraduate Discrete Mathematics. You write correct, well-tested JavaScript, and you never ship a puzzle that has not passed an automatic correctness check.

## Goal
Build **one self-contained HTML file** (inline CSS and JavaScript, no external libraries, no network calls, works offline when opened from disk or any static host such as GitHub Pages or an LMS). It holds three mini-games for a one-week classroom pilot on expression trees and graph traversal. The pilot supports a pedagogy paper, so it needs (a) puzzles generated by a program and checked by a validator, (b) anonymous per-student logs tagged with misconception codes, and (c) CSV export for the instructor.

## Audience and context
- Undergraduates who have just practiced building expression trees and are starting graphs.
- Students identify themselves only with a self-generated anonymous code: the first two letters of their mother's (or a guardian's) first name, their birth day as two digits, and the last two digits of their phone number, e.g. `MA0742`. The same code goes on the paper pre/post quiz.
- The games must feel like a game, not an assignment.

## Game 1: Expression Trees (story region: "The Clockwork Forge")
Operators `+ - * / ^` with standard precedence (`^` > `* /` > `+ -`). All operators are left-associative except `^`, which is right-associative. Leaves are distinct letters, or digits 1 to 9 in Evaluate mode. Four modes:
1. **Build the tree** from an infix, prefix or postfix string (selectable, or mixed). Interaction: the tree starts as one empty "?" slot. The student clicks a slot, then a token chip (each token from the expression is used once). An operator creates two child slots, and clicking a filled node clears its subtree. Do not auto-select the next slot in preorder, because that would give away prefix order.
2. **Traversal race:** a generated tree is drawn. The student clicks every node in the requested order (preorder, inorder or postorder). The sequence is checked when complete, with Undo and Clear.
3. **Spot the error:** show an infix expression and a tree with exactly one injected mistake (a precedence error, an associativity error, swapped operands of a non-commutative operator, or a wrong operator). The student clicks the highest node whose subtree is wrong and picks the error type. The correct node is the top-most node where the two trees differ. After a correct answer, show the right tree.
4. **Evaluate:** an integer-valued expression in infix, prefix or postfix. The student types the value, and a timer is shown.

Infix rendering must use the minimum parentheses (fully parenthesized at level 1). Build a real shunting-yard parser with three modes: standard; `flat` (ignore precedence, read left to right); and `rassoc` (group same-precedence operators from the right). The last two model student misconceptions.

## Game 2: BFS vs DFS Explorer (story region: "The Lantern Caverns")
- A generated connected, near-planar graph: 6 to 10 vertices on a jittered 3x4 grid. Edges join neighboring cells, with no crossing diagonals. Start from a random spanning tree and add extra edges at random. Labels are letters assigned at random.
- The task is to run BFS or DFS (selectable or mixed) from a given start vertex. **Ties are broken alphabetically.** DFS means recursive DFS.
- The start vertex is pre-visited. The student clicks vertices in visit order, with instant feedback on every click.
- A side panel shows the frontier before each step: the queue (front on the left) for BFS, or the stack as the current DFS path (top on the right) for DFS. At the top level the panel is hidden.
- Visited vertices are colored and numbered, and tree edges are highlighted. At the end, the BFS or DFS spanning tree is visible.

## Game 3: Euler Path Hunter (story region: "The Bridge Isles")
- Step 1: the student classifies the graph as *Euler circuit exists* / *Euler path but no circuit* / *Neither*. Degrees are shown at level 1, revealed by a "hint" button at levels 2 and 3 (logged as a hint), and hidden at level 4.
- Step 2 (if one exists): the student traces it by clicking a start vertex, then adjacent vertices along unused edges. Used edges are numbered. Provide Undo and Restart.
  - Starting a path at an even-degree vertex is rejected immediately with an explanation.
  - A non-edge or an already-used edge is rejected.
  - If the student is stuck with edges left, it is logged once as a burned bridge.

## Validated generation (core research claim)
Every puzzle comes from `generate(make, validate)`: propose a random candidate, run every check, and on failure count each failed check by name and propose again (up to a cap). Each delivered puzzle logs one `gen` row with `candidates` tried and `rejects` as `reason:count|...`. Required checks:
- **Expression trees:**
  - every internal node is an operator with exactly two children, and every leaf is an operand;
  - exact structural round-trip through infix (at the displayed parenthesization), prefix and postfix parsing;
  - no duplicates of recent puzzles;
  - level 2 and up for infix Build: precedence or grouping must matter (the `flat` or `rassoc` parse differs);
  - Spot the error: the mutated tree must differ in value from the correct one (random-assignment equivalence test with at least 3 finite trials);
  - Evaluate: every intermediate value an integer, |value| ≤ 500, no division by zero, exponent ≤ 3. The puzzle must also be *discriminating*: the misconception parse (`flat`/`rassoc` for infix, operands in the wrong pop order for prefix/postfix) must give a different value.
- **BFS/DFS:** valid simple graph (no unknown vertices, self-loops or multi-edges); connected; at least as many edges as vertices; BFS order ≠ DFS order; at least 3 tie-break decisions; not a duplicate.
- **Euler:** connected; edge count in range; the number of odd-degree vertices matches the target class (0 = circuit, 2 = path, ≥ 4 = neither; choose the target class first, then reject graphs until one matches). Confirm existence independently with Hierholzer's algorithm in the self-test.

Also include:
- **Puzzle pack validator** (Instructor tab): paste JSON puzzles, for example ones written by an LLM, and check them with the same rules. Report each failure with the correct value, e.g. `postfix-mismatch (should be a b - c *)`, and log the results as `gen` rows with `source=pack`. Formats: `{"game":"expr","mode":"build|traverse|evaluate","format":"infix|prefix|postfix","infix":..., "prefix":..., "postfix":..., "value":...}`, `{"game":"bfsdfs","vertices":[...],"edges":[[u,v],...],"start":..., "bfs_order":[...], "dfs_order":[...]}`, `{"game":"euler","vertices":[...],"edges":[...],"claim":"circuit|path|none","example":[...]}`.
- **Self-test button:** generate many puzzles per mode and level, re-verify each one with independent checks, and print the failure counts.

## Misconception diagnosis and codes
Diagnose each wrong answer by comparing it with the answer a known misconception would produce, then tag it with a fine-grained `subtype` and a shared `misconception` code [these codes match the pilot quiz key]:
- **M1** Precedence: the answer equals the `flat` parse or its value.
- **M2** Operand order or associativity: the answer equals the `rassoc` parse; the tree needs a swap at `- / ^`; the value equals evaluation with operands popped in the wrong order; or the tree is regrouped but value-equivalent. A tree that differs only by swaps at `+` or `*` is accepted as correct, with a note about convention.
- **M3** Traversal order: the student gave another traversal, mirrored it (right before left), reversed it, or read prefix as postfix or the other way round.
- **M4** BFS/DFS frontier, for BFS: chose a just-discovered neighbor of the last vertex instead of the queue front (`dfs-like`), took the newest queue item (`lifo-instead-of-fifo`), or skipped ahead in the queue. For DFS: went to a neighbor of a lower stack vertex instead of the top (`bfs-like`), or backtracked too far (`backtrack-error`).
- **M5** Visited tracking: revisited a vertex, reused an edge, or moved along a non-edge.
- **M6** Euler condition: applied the all-even rule to a path, confused circuit with path, missed an existing circuit, or claimed one exists when there are ≥ 4 odd vertices.
- **M7** Euler start: began an Euler path at an even-degree vertex.
- **OTHER**: tie-break order, arithmetic slips, other structure errors.

Every wrong answer gets a short, student-friendly explanation of the misconception.

## Adaptivity (just-in-time micro-variants)
- Levels 1 to 4 per game: go up after 2 first-try solves in a row, and down after 2 puzzles with 2 or more errors. Levels control operator count (2, 3, 4, 5 to 6), the operator set, parentheses, vertex count (6, 8, 9, 10) and whether the frontier and degrees are shown.
- **Targeted practice:** if the same subtype appears 2 or more times in a student's last 6 errors in a game, the next puzzle must exercise that misconception. Add it as a validator constraint (e.g. require `flat` ≠ tree for precedence), and show a "Targeted practice: …" label. If the constraint can't be met, generate without it.

## Logging and data export (research)
- First screen: anonymous code (3 to 12 letters or digits) and a required consent choice (Yes, my anonymous data may be used for research / No). Everyone can play either way.
- One CSV row per event, stored in `localStorage`. Columns: `ts, student, consent, session, kind, game, mode, level, puzzle_id, source, focus, puzzle, attempt_no, correct, misconception, subtype, response, expected, time_ms, candidates, rejects, detail`. Kinds: `attempt`, `gen`, `skip`, `hint`, `session-start`, `profile`, `badge`. `time_ms` is measured from when the puzzle appeared. Leaving a puzzle unsolved logs a `skip`.
- Student Home page: "Download my data (CSV)" plus a "Copy my data" fallback (clipboard, or a textarea if that is blocked).
- Instructor tab:
  - merge many student CSVs (dedupe, download all or consented rows only);
  - summary of attempts and errors by game and code;
  - validated-generation table (puzzles, candidates, first-pass acceptance %, rejections by check);
  - clear data with a two-click confirm (no `confirm()` dialogs);
  - pack validator and self-test.

## Story, companions and rewards (engagement layer, display only)
These must never change puzzles, validation, diagnosis or codes.
- **Story:** "The Kingdom of Nodeland has gone dark." The student is an apprentice restoring three regions, each with a mentor character and four chapter scenes that unlock at 0, 3, 8 and 15 solves. Each scene restates the key concept in story form:
  - Clockwork Forge (mentor Master Gearwright): engines are trees; multiplication gears turn before addition gears; spot the saboteur's swapped gears.
  - Lantern Caverns (mentor Mossa): ripple-lighters use a queue (BFS), rope-runners use a stack (DFS); mark visited caves or walk in circles.
  - Bridge Isles (mentor Mayor Tidewell): count the bridges at each island; odd islands must be where the parade starts or ends; don't burn your bridges.
- **Companions:** six original characters drawn as inline SVG from simple shapes (no emoji or copyrighted characters): a fox, owl, robot, cat, dragon and space explorer, each with a name and a one-line personality. Each has happy, sad, neutral and surprised expressions. The companion appears bottom-right with a speech bubble: cheers on a solve, gentle nudges on a miss. Students choose one after sign-in and can change it later (logged as `profile`).
- **Rewards:**
  - XP per solve: 10, +5 first try, +2 per streak step up to 5, +3 per level above 1.
  - Ranks: Apprentice, Pathfinder, Tree Whisperer, Graph Ranger, Grand Cartographer, Legend of Nodeland.
  - Coins, a streak flame, and 11 badges, each logged as `badge`: first solve; 10 solves per region; all three regions; 5 and 10 first-try streaks; solved after 3 or more misses; Evaluate under 10 s; level 4; 5 sabotages spotted.
  - Feedback: confetti, a floating "+XP", badge toasts, a rank-up story card.
  - A map-style home page with region cards and restoration progress bars, plus a badge shelf.
  - Respect `prefers-reduced-motion`.

## UI and quality requirements
- Clean, responsive layout that works on laptops and tablets. Trees and graphs are drawn in SVG with click targets on nodes. Use clear color states: selected, visited, current, wrong flash, tree edges, used edges.
- No `alert`/`confirm`/`prompt`. Pressing Enter in an input must not also trigger the next button.
- Wrap `localStorage` access in try/catch.
- Before finishing: run the self-test (target 0 failures over 1,000+ generated puzzles). Then play every mode once in a headless browser, including one wrong answer per game, and check that the CSV rows carry the expected codes. Also check known answers, e.g. `6 2 3 + * 4 -` = 26; BFS from A on `A-B, A-D, B-C, B-E, C-F, D-E, D-F` = A B D C E F and DFS = A B C F D E.

## Deliverables
1. `dmath-games.html`: the single-file game.
2. `README.md`: short instructor notes covering hosting, the student workflow, the CSV columns, the misconception codes, how validation works, and the pack JSON format.
